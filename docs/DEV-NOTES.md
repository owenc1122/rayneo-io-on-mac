# RayNeo io on Mac

目标是运行原版眼镜系统、显示真实系统画面并接收输入的单窗口模拟器。当前已经显示原固件生成的开机标志，尚未进入可操作桌面，整机模拟器未完成。

## 本地运行

构建：`sh scripts/build-app.sh`。启动：`sh scripts/run-app.sh`。

运行依赖当前 checkout、`.local/renode` 和 `.local/firmware.bin` 指向的本机固件。尚未打包为可移植应用。本机直接运行可启动后端并显示开机图像；通过 Finder 启动的一次检查停在读取 Documents 内文件，原因尚未最终确认，不把 Finder 启动列为通过。

应用只展示当前模拟运行写出的显示缓冲区，不载入历史截图或导航演示。每次运行记录位于 `.local/runs/ui-*/`，包含 `boot.log` 和收到的 `frame.pgm`。

## 已验证（2026-10-13）

- 原版 AP 固件未经指令修改，已进入 NuttX 内核并完成所观察到的 board 初始化调用。AP 与 BTC 控制器代码均在模拟 CPU 上执行。
- 显示控制器读取固件实际写入的内存，输出开机图像；Mac 窗口已通过可视检查。当前按观察到的单字节亮度数据呈现，最终双屏布局、完整分辨率和其他显示格式尚未验证。
- GPIO 软件 SPI、硬件 SPI、屏幕寄存器读写、LCD DMA 完成中断、I2C 控制寄存器具备启动所需的初步模型。GPU 仅支持初始化寄存器；尚未执行绘制命令，也不会假报绘制完成。
- NOR/NAND、NAND 缓存地址、DMA 真实数据搬运及完成状态通过专项检查。原固件能够格式化并挂载模拟 NAND，但它仍是空白启动后创建、仅保存在内存中的文件系统。
- Swift 的 PGM 解码检查通过；存储及屏幕模型分别由 `python3 scripts/check-storage.py` 和 `python3 scripts/check-panel.py` 验证。这些检查不等于桌面和交互验收。

## 当前阻塞和未完成项

AP 在打开 BTH 子系统时读取 `0x28000000` 的固件头；正式板级配置尚未装入 BTH 镜像，因此启动失败。现有 `nuttx_bth.bin` 是 OTA 包，首字为 `0xffffffff`，而 AP 启动路径检查 `0xbe57ec1c`。不能把原始升级包等同于已安装存储镜像。启动元数据的安装流程仍待证实，未通过修改固件指令跳过检查。

`.local/research/bth*.repl` 和对应探针用于单独研究 BTH 复位入口及地址别名；尚未整合进正式配置。其他处理器、BTH 核间通信、GPU 绘制、资源文件系统和输入仍未完成。OTS 标识、存储器 ID、PHY、时钟及部分外围寄存器包含从固件推断的假设，未做实机校准。

所有工作仅保存在本地项目，没有上传固件或刷写实体眼镜。
